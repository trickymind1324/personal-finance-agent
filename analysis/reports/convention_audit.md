Key structural insights encoded as invariants:

1. `affordable_with_plan` + `full_payment` occurs only when `earliest > deadline` (samples 06, 11, 21): full payment alone misses the deadline, a permitted spending change makes today safe. Rule 1 (complete by deadline) outranks rule 2 (no changes).
2. `installments` is chosen with `earliest == request_date` (sample 12): the user accepts only installments (or partial|installments), so full payment is ineligible even though capacity exists. `earliest` is capacity-only.
3. `wait` is chosen over `partial_payment` when the user does not accept partial (03, 04, 08, 13, 18, 23 — none accepts partial or the request forbids it).
4. `not_affordable` rows still carry a nonzero `amount_safe_to_pay`; the earliest date is empty (never safe in 90 days); partial is impossible because it needs an earliest date ≤ deadline.
5. `reduce_to` new amount is exactly the event's `minimum_allowed_amount`; the targeted event id is the LATEST settled occurrence of that recurring description.
